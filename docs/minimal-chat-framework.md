# 最小聊天框架：运行与验收

## 立即运行（无需模型密钥）

在已经安装依赖的 `hackson-cityu` 环境中，从仓库根目录运行：

```bash
conda activate hackson-cityu
python scripts/dev_local.py --demo
```

默认前端 http://127.0.0.1:5173，后端 8000。若端口占用：

```bash
python scripts/dev_local.py --demo --port 5175 --api-port 8001
```

一个终端启动两个服务，Ctrl+C 同时停止。会话和附件保存在 `apps/api/.data/local-demo/`，重启后仍保留。该目录及生成的本地令牌被 Git 忽略。脚本不覆盖正式 `.env`。首次安装依赖可执行 `npm ci` 和 `python -m pip install -r apps/api/requirements.lock`。

**本地联调模式不是云端 AI。** 它通过真实 HTTP、认证、数据库、Agent 运行和文件检索验证链路，使用明确标注的确定性回答，不调用模型，不生成向量，也不做模型语义审校。

## 切换云模型

1. 执行 `python scripts/setup_local.py`，生成后端与数据库配置。已有配置不会覆盖。
2. 在 `apps/api/.env` 填写百炼密钥及地域地址，核对模型和数据库地址。
3. 启动 Docker 中的 PostgreSQL / pgvector：

   ```bash
   docker compose --env-file infra/.env -f infra/compose.yaml up -d
   ```

4. 启动：`python scripts/dev_local.py --cloud`。

云模式使用既有 QwenProvider 与 PostgreSQL。未配置或不可用时直接显示错误，不自动回退联调模式。真实云模型与 PostgreSQL 的运行仍需使用自己的配置验收。

## 当前打通范围

- 新建会话 → 发送消息 → 发起后端运行 → SSE 运行状态 → 最终回答 → 后端历史保存。
- SSE 是运行状态流；当前模型适配仍一次返回最终内容，尚非逐 token 输出。UI 不用假打字动画冒充 token 流。
- 通过代理注入后端令牌，浏览器不持有 API_TOKEN / 模型密钥。
- 会话创建和运行请求使用稳定请求编号；网络故障后重试复用编号，避免重复消息。
- 状态流中断后可恢复已有运行连接，不重新发起模型任务。
- 停止回答、失败消息原位重试、切换会话后写回原会话。
- 勾选“附上本地书墙相关资料”时，将命中节选上传为后端会话附件，由后端文件工具返回引用，支持查看来源。
- 三个技能表单进入同一聊天链路，并映射对应办公室伙伴。角色共用当前后端模型，不代表三个独立桌面执行器。
- 完成 / 失败 / 取消同步到本次办公室任务。任务概览与 Token 仍是界面统计 / 估算。
- 旧版本地演示对话保留为只读记录，不自动上传；新对话使用后端。后端会话在刷新、重新打开或重启服务后可以恢复。

知识墙仍使用浏览器本地资料，不是完整云端知识库同步。本轮不写入长期记忆，定时任务仍需页面打开并模拟交代工作。真实桌面执行、后台调度、完整知识库迁移不在最小链路内。

## 测试

```bash
npm run check
npm test
npm run build
cd apps/api
python -m pytest -q --ignore=tests/test_retrieval_prd.py
```

忽略的三个历史文档测试依赖仓库原本缺失的 `docs/memory-retrieval-observability-prd.md`；不是本轮功能测试。未忽略时全量仍会报告这三项失败。

启动本地联调服务后，从根目录执行实际 HTTP 验收：

```bash
AGENT_TEST_URL=http://127.0.0.1:5175 node scripts/test_chat_http.mjs
```

该验收只允许显式联调模式，会创建并清理自己的测试会话。覆盖前端代理、认证、请求幂等、附件检索、状态流、回答、来源、历史、取消与原位重试。

另外的测试覆盖 UTF-8 分片、CRLF、心跳、截断状态流、网络错误、切换会话、旧记录保护、本地数据库跨实例持久化。现有模型协议替身测试保留；这些结果不等价于真实云端验收。

## 人工验收

1. 新建对话，确认顶部明确显示运行模式，发送一句话，等待后端回答。
2. 勾选附带书墙资料，问“光合作用”，打开回答下的来源。
3. 刷新页面，从侧栏恢复会话，确认消息仍在。
4. 发送后立即停止；消息下重试时，原用户消息不重复添加。
5. 在回答中切换到另一会话，确认答案仍保存到原会话。
6. 从技能工具栏提交要求，确认跳转到对应伙伴的后端对话。
7. 停止后端时应显示连接错误；重启后可以重新连接或恢复未结束的回答。

部署 `dist/` 时仍需服务器提供同源 `/api/v1`、`/api/v2` 和 `/api/knowledge` 代理及认证配置；Vite 开发代理不会自动进入静态构建产物。

## 本轮验收结果

- 前端语法 / 导入检查、全部前端测试、生产构建通过。
- 后端功能测试 118 通过、1 跳过；另有三个已知历史文档测试因原始 PRD 文件缺失未纳入功能测试命令。
- 实际 HTTP 验收通过，测试会话已清理。
- 服务实际停止并重新启动后，先前会话和不重复的重试结果仍可从后端恢复。
- 浏览器验证：发送并接收后端答案、读取附件引用、停止回答、原位重试（消息仍两条）、刷新恢复；从新地址来源加载同一后端历史；技能表单自动进入后端会话。
- 390px 布局检查无横向溢出，来源采用浮层，不挤占消息和输入区域。
- 使用测试标记构建后确认：后端令牌未进入任何构建资源。
- 仍未做真实百炼 / PostgreSQL 联调；生产包仍有超过 500KB 的资源体积提示。
