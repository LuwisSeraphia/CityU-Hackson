# 维港拾光：前端视觉优化、卡片连接交互 PRD 与接口合同

版本：1.1 · 日期：2026-11-03 · 状态：待实现规格。本次更新设计文档，不表示界面已改造或视觉验收已通过。

依据：[总 PRD V2.1](personal-knowledge-companion-prd-v2.md)、[实施记录](knowledge-v2-implementation.md)、现有 knowledge/router.py、service.py、前端代理与 UX-CONTRACT.md。本文件只细化第一条可用交互链；接口标为“补齐”的能力不得当作已经存在。

## 1. 目标与范围

用户在真实工作台创建两张卡片，说明它们为什么相连，保存后可从任一端查看、编辑或撤回；刷新和切换聊天后仍可找回。采用用户指定的香港维港海边唯美风格，保留系统字体、来源展示与全部业务规则；不新增大型图谱。视觉方向名“维港拾光”仅用于设计沟通，不自动替换产品名称 Personal Agent。

本期覆盖工作台外壳、欢迎页、聊天/输入、知识库、卡片与连接、来源详情和服务状态的统一外观。模式为 Operate，阅读内容为 Read：氛围服务于长期记录与阅读。第 7–12 节为新视觉规范；第 2–6 节的交互、接口与验收继续有效。

本期仅连接 V2 通用条目，不支持把旧事实、旧事件、文件块直接作为端点。两端必须属于同一个当前集合；跨集合连接留到授权范围规则实现后。AI 推荐、聊天自动创建连接、连接语义检索为后续，不显示无效入口。建立连接表示用户自己的解释，不代表客观因果。

## 2. 页面与信息组织

工作台侧栏新增“我的知识库”，与现有“我的记忆”区分。打开工作台内模态视图，沿用原生 dialog、Button、TextEditor 和来源详情样式，避免嵌套 dialog；创建/详情/编辑/选择目标为同一浮层内部步骤。

| 视图           | 内容与主要动作                                                                  |
| -------------- | ------------------------------------------------------------------------------- |
| 集合与卡片列表 | 集合选择、新建集合、搜索、类型筛选、卡片摘要、创建时间、分页；新建卡片          |
| 卡片详情       | 完整正文、类型、模态、版本与时间；修订、查看历史；连接列表和“连接另一张卡片”    |
| 选择目标       | 固定起点摘要；当前集合内搜索/浏览；排除自身；选中目标后可查看完整内容           |
| 编辑连接       | 两端完整正文可展开；方向提示“A → B”；必填“你为什么把它们联系起来？”；保存、取消 |
| 连接详情       | 两端、方向、用户原话、状态、版本与修改时间；跳转、编辑说明、查看历史、撤回      |
| 连接历史       | 每版说明、当时端点版本、操作及时间；只读，不直接覆盖或恢复                      |

不把假设显示为已证实事实。关系在两个端点均显示，但从 B 查看时提示“A → 当前卡片”，不反转含义。第一版方向固定为用户选择顺序；修改方向需要撤回并重新创建。

本视图生命周期约定：内部返回保留集合、搜索、页码和滚动位置；关闭整个知识库后清空列表条件，私有正文和搜索词不写 URL/localStorage。此约定只适用于新知识库，旧记忆模态保持原规则。有未保存正文时关闭/切换编辑步骤需确认放弃；用户确认后才清空草稿。保存进行中禁止关闭。

## 3. 核心流程与状态

### 3.1 创建与浏览

无集合时提供“创建第一个集合”；有集合无卡片时提供“记录一个想法”。新建卡片需选择集合、输入正文，标题可选，类型默认 note；思想类型与是否假设分开设置。保存成功后打开详情；失败保留输入。新卡片无需连接也能保存。

列表必须有不输入关键词就能浏览的接口，不能通过伪造搜索词实现。搜索采用提交式；中文输入法候选确认不触发搜索。集合/类型/搜索变更重置分页，旧请求晚返回不得覆盖新条件结果。

### 3.2 创建连接

卡片 A → 选择 B → 同屏核对内容 → 写解释 → 保存 → 返回 A 详情并显示新连接。提交包含两端 version_id。重复点击按钮锁定；超时后用同一幂等键重试；修改请求正文后使用新键。

同一对卡片允许不同说明并存；不以端点唯一约束阻止新联系。相同请求重试返回同一连接。空白解释与自连接由前后端共同拒绝。保存成功才出现在正式列表，不提前显示成功。

### 3.3 修订、复核与撤回

编辑只修改连接说明；保留旧版本。若端点已变化，显示当时版本和当前版本，要求用户明确选择“按当前卡片重新确认”，不得把普通编辑暗中当作确认新端点。

撤回确认展示两端标题与影响：“停止把这条连接作为当前关系；历史说明仍可查看。两张卡片不会被删除。”确认后从默认列表移除；“查看已撤回”中可访问历史。本期不提供恢复按钮。

端点删除：当前连接不可用，端点内容不回显；依照总 PRD 清理对应解释，历史仅显示失效占位，不能借历史接口读回已删除文字。

| 状态         | 交互行为                                                     |
| ------------ | ------------------------------------------------------------ |
| 加载         | 保留布局、说明加载中，不显示伪空态                           |
| 空结果       | 展示无匹配，可清空搜索或返回列表                             |
| 保存失败     | 表单保留；显示可理解原因和重试                               |
| 409 版本变化 | 保留草稿；加载最新内容并重新比较；不自动重提                 |
| 404 不可访问 | 隐去原正文，提示已删除或无权访问；可返回列表                 |
| needs_review | 标“卡片已修改，连接待复核”；允许查看历史，不作为当前有效关系 |
| withdrawn    | 默认列表隐藏；历史显示已撤回，不再自动应用                   |
| 请求超时     | 标“保存结果待确认”；同键重试，不提示确定未保存               |

键盘可完成全部操作；初始焦点进入标题/首个输入，错误后聚焦错误字段，返回恢复触发位置。窄屏按单列显示端点，正文可滚动；颜色配合文字，连接按钮不依赖悬停出现。

| 功能                | 现有接口                               | 本期所需变更                                      |
| ------------------- | -------------------------------------- | ------------------------------------------------- |
| 集合创建/读取       | POST/GET /api/v2/collections           | 增加有界分页；前端适配                            |

| 创建连接            | POST /connections                      | 增加同集合/自连接校验、正式连接版本记录与并发幂等 |
| 查看端点连接        | GET /items/{id}/connections            | 补端点标题、固定版本、连接版本、状态、分页        |
| 连接详情            | 无                                     | 新增 GET /connections/{id}                        |

| 撤回连接            | 无                                     | 新增 POST /connections/{id}/withdraw              |
| 连接历史            | 无                                     | 新增 GET /connections/{id}/history                |
| 浏览器代理          | 现有 /api/agent 仅允许 V1 路径         | 新增 V2 同源代理，凭据只在服务器                  |

### 4.1 公共合同

服务端使用现有认证确定 owner。新代理 `/api/knowledge/[...path]` 转发至配置的 `AGENT_KNOWLEDGE_API_URL`（默认 `http://127.0.0.1:8000/api/v2`）；不要修改既有 V1 base 让旧接口失效。仅放行 collections/items/connections 及本期需要的方法；保留本机同源与路径校验，透传 Idempotency-Key，禁用缓存，令牌不下发浏览器。

写入必须带 Idempotency-Key（1–128 字符），唯一范围 owner＋操作＋资源＋key。同 payload 返回原结果；不同 payload 返回409 IDEMPOTENCY_CONFLICT。并发同 key 不能泄漏数据库唯一约束异常，需读取已提交结果或返回可重试处理中。撤回/删除优先于旧回执重放，不能返回过时正文。

列表统一 `{items,next_cursor}`，limit 默认20、上限100，按 created_at/id 稳定排序；游标绑定过滤条件，不允许换过滤条件复用。时间输出 UTC ISO8601，界面以 Asia/Shanghai 显示。

### 4.2 条目浏览与端点 DTO

`GET /items?collection_id=...&query=...&kind=...&cursor=...&limit=20`：query 可空，kind 可省略；只返回 owner 范围内 active 的 V2 条目，不能混入文件片段或旧事实。每项包含 id、title、text_preview（最多160字）、kind、modality、version_id、created_at、updated_at、collection_ids。

`GET /items/{id}` 在现有字段基础上补 collection_ids、updated_at。正文不截断；版本历史逐页返回。目标选择与列表共享此接口合同和 schema。

连接端点对象统一为 `{id,title,version_id,current_version_id,availability}`，availability=available/deleted/unavailable；不可用时 title 为中性占位，不泄露内容。连接 DTO 包含：id、version_id、version、from、to、explanation_raw、usage_status、lifecycle、created_at、updated_at。usage_status=ready/needs_review，lifecycle=active/withdrawn/deleted。

`GET /items/{id}/connections?collection_id=...&include_withdrawn=false`：任一方向匹配；两端均须属于当前集合且可访问。列表仍返回原始方向，不因查询端点反转。

### 4.3 连接写入合同

`POST /connections` 请求沿用 from_id、to_id、from_version_id、to_version_id、explanation_raw，增加 collection_id。说明去除首尾空白后1–8000字。服务器同事务锁定端点并检查 owner、集合、active、当前版本，创建连接及第一版，201返回完整 DTO。

`PATCH /connections/{id}` 请求：base_version_id（连接版本）、from_version_id、to_version_id、explanation_raw、reconfirm_endpoints（默认false）。普通编辑要求端点仍与原连接版本一致且当前未变化；端点变化返回409。重新确认必须 reconfirm_endpoints=true 并提交当前端点版本。两种操作均追加连接版本；旧版本不可覆盖。已撤回连接拒绝编辑。

`POST /connections/{id}/withdraw` 请求 base_version_id；200返回 lifecycle=withdrawn 的 DTO，追加撤回历史。撤回不删除卡片，必须失效相关连接检索索引和派生模式应用。

`GET /connections/{id}/history` 返回各版 explanation_raw、两端当时 version_id、operation(create/edit/reconfirm/withdraw)、created_at、version_id；删除清理规则优先于历史展示。

错误沿用现有 error envelope。409：KNOWLEDGE_VERSION_CONFLICT / CONNECTION_VERSION_CONFLICT / IDEMPOTENCY_CONFLICT；422：CONNECTION_SELF_LINK / INVALID_TEXT；404：EVIDENCE_UNAVAILABLE 或不存在；越集合范围不返回目标正文。错误可带当前可访问版本 ID，正文必须经正常详情接口读取。

## 5. 数据迁移与代码任务

现有 Connection 单行同时存正文与端点，尚无关系版本。新增 connection_versions，以 connection_id/version 唯一，保存端点版本、原话和操作；Connection 增加 current_version_id/lifecycle。迁移将每条已有连接回填为第一版，保留 ID、created 和 needs_review；已删除解释保持为空，不从来源重建。

## 8. 视觉方向：维港黄昏与安静的阅读空间

### 8.1 场景与画面层级

灵感：海旁步道望向维港，蓝灰海面、空气中的湿润雾感、夕照的淡杏色、远处层叠天际线。重点是空间、光和安静，不是旅游广告、夜店霓虹或满屏玻璃。

画面分三层：最底层为静态海雾/海面氛围；中层为低对比地平线和远景；前层为近乎不透明的阅读面板。输入框、错误信息、候选审核不得透明叠在复杂图片上。天空允许缓慢色阶过渡的静态渐变，这是本主题有意采用的规则；按钮与正文不使用渐变填充。

首页欢迎区使用一幅横向维港远景（桌面约220px高、手机140px），展示天空、海面及少量岸线。开始聊天后折叠为64–80px标题区；关闭装饰不改变功能布局。现有聊天记录进入时不播放欢迎展开动画。知识库编辑区域不放整幅照片，仅在标题边缘保留淡淡海雾色。

建议素材：一幅自有/许可清晰的维港黄昏横幅，另备移动裁切。开发前记录来源、许可及裁切焦点；AI生成素材标记“维港意象”，不称为真实地点摄影。交付素材前可使用明确标注的占位静态渐变，不把占位宣称为完成的维港视觉。装饰图 alt=""、aria-hidden；照片不包含用户私人数据。无需用户提供素材才能编写本规格。

## 9. 各界面的完整视觉与交互规范

### 9.1 工作台、欢迎与聊天

桌面侧栏保持256px，海雾实色底，选中项深海蓝文字＋浅蓝背景＋左侧标记；不只靠颜色辨认。保留对话历史与新对话。顶栏显示页面标题、真实服务状态和知识库入口，风景不能挤占操作区域。

欢迎区保留现有产品文案，不新增关于模型能力的承诺；建议提示“记下今天的想法，或接着上次的事情聊”。建议提示不得伪装已记住用户近况。聊天开始后以正文为中心，用户气泡浅蓝底，AI正文白底或无气泡，不使用大面积粉色。AI头像保持产品标识，不拟人化成正在凝视用户的角色。

输入区保持布局底部，纯白基底、细边框；提问/记录、智能记忆、上传、临时对话、停止按钮保留可达。次要工具可归入可展开区域，但记忆开关和当前模式不能隐藏。完成答案全文展示，不做假打字流；工具处理中可以用单一状态点，不把长时间等待包装成“正在想你”。

### 9.2 知识库与卡片详情

宽屏模态 max-width 1120px、max-height calc(100dvh - 64px)，顶区固定标题/关闭，次区固定集合与搜索。列表360px、详情弹性；未选卡片时详情用简短操作提示，不能填充假的知识。旧记忆列表继续使用原入口。

每条卡片呈现类型、标题、最多两行摘要、时间；关系数量只在后端确有字段时显示，否则不猜。选中卡片用边框/标记/文字共同表达，不使整个列表抖动。详情中正文优先，来源与版本次级，“连接另一张卡片”为清楚的次主操作。

### 9.3 连接编辑与反馈

桌面 A/B 两端左右并排，中间一条细连接线与方向箭头；说明框在下面占满宽度。端点卡片标题常显，长正文各自可展开；手机改为 A、方向文字、B、说明的顺序。连接线是方向提示，不能代替文字标签。

选择目标后：目标卡片边框亮起一次，连接线在180ms内淡入。此时文案为“准备建立连接”，线为中性/虚线，不表示已保存。保存服务端确认后：线在280ms内完成一次描绘，出现“连接已保存”及对勾，再返回详情并把焦点移至新连接。动画不阻挡下一操作，不增加保存等待。

冲突时保留原解释并显示“卡片内容已更新”；下方对比当时/当前内容，重新确认按钮使用文字明确后果。撤回后条目淡出一次，撤回确认使用清晰实色面板，不用漂浮消散效果掩盖操作影响。

### 9.4 来源、历史、服务状态

来源抽屉与历史保持白底、深色正文、海蓝定位标签。文件页码和原话可复制，标签不做闪烁动画。错误和服务未连接采用稳定信息块、明确重试或配置入口；风景可保留在边缘，但错误不覆盖在照片上。真实/演示标签持续可见，动画不能混淆两者。

### 9.5 空、忙、错、成功的统一表达

空集合：“还没有卡片”＋“记录一个想法”；搜索空：“没有找到匹配内容”＋“清空搜索”。初次空态可用简洁静态海平线图形，不能放虚构记忆。请求中的按钮保持尺寸，文字“正在保存”；失败原位说明并保留草稿；成功通知使用 aria-live=polite，状态在详情中持久可查，不能只依靠短暂 toast。

## 10. 动效合同

| 触发              | 属性与时长                            | 规则                                       |
| ----------------- | ------------------------------------- | ------------------------------------------ |
| 按钮 hover/focus  | 颜色/边框，120ms                      | focus立即可见，键盘与触屏不依赖hover       |
| 按下按钮          | translateY(1px)，80ms                 | 不改变布局尺寸，无弹簧过冲                 |
| 打开模态          | opacity＋translateY(8px)，220ms       | 原生dialog立即建立焦点约束；动画只控制内层 |
| 内部步骤切换      | opacity，160ms                        | 不滑动整个窗口，不回到列表顶部             |
| 选择卡片          | 边框与背景，140ms                     | 不放大卡片、不改变邻项位置                 |
| 连接保存确认      | SVG stroke-dashoffset＋opacity，280ms | 只在后端成功后一次；不会用于大批量列表     |
| 新消息/新卡片进入 | opacity＋translateY(4px)，180ms       | 用户停留旧消息时不强制滚至底部             |
| 撤回成功          | opacity，160ms                        | 后端确认后移除，焦点转到相邻有效控件       |
| 请求加载          | 单个小旋转指示，900ms循环             | 仅忙碌期间；无整屏波浪/闪光                |

统一 easing：cubic-bezier(.2,.7,.2,1)。背景默认静态，不使用持续海浪视频、鼠标视差或随时间自动换色。先前150ms统一过渡在开发时按本表扩展为集中 motion token，不散落硬编码。

prefers-reduced-motion: reduce 下取消位移、路径描绘和旋转；直接切换状态或≤80ms透明度变化，静态“处理中”文字仍显示。forced-colors 下移除装饰背景、阴影与透明效果，保留系统轮廓和状态文字。声音/震动默认不加入。

不动画 height/width/top/left，不逐字抖动正文；大面积 backdrop-filter 不启用，只有小面积顶栏可选且必须有实色回退。动画可被新操作中断，结束回调不能承担保存、路由或审批业务逻辑。

## 11. 响应式、资源与代码落地

| 视口              | 布局                                                                   |
| ----------------- | ---------------------------------------------------------------------- |
| ≥1200px           | 侧栏256px，聊天居中；知识库列表/详情双栏；连接端点双栏                 |
| 768–1199px        | 侧栏按可用空间收为按钮/原生抽屉；知识库以单列步骤为主，不硬挤三栏      |
| <768px            | 原生dialog内全屏步骤，安全区留白16px，顶部返回/标题/关闭，底部操作可达 |
| 390×667与200%缩放 | 正文自然换行、无水平整页滚动；键盘出现时输入可滚入可见区               |

使用100dvh和安全区 inset，避免移动软键盘遮挡保存。可点击目标至少44×44px或等效间距。正常文本对比度至少4.5:1，大字3:1，关键控件/焦点3:1；应在实际合成背景验证，不仅检查色值。

装饰素材采用本地AVIF/WebP，桌面目标≤250KB、移动≤120KB，指定宽高/比例，加载失败退回海雾实色；不让图片占位引起布局跳动。无外部字体依赖、无第三方图片追踪请求。完成标准包含目标设备上输入响应无可见卡顿、装饰不引发长任务；主交互目标 INP≤200ms、CLS≤0.1，需测量后记录，不视为已达标。

代码落点：DESIGN.md 为 token 单一来源；扩展 generate-tokens.mjs 支持 surface、motion 和主题背景 token；globals.css 只维护全局及共享样式。Button/Modal/TextEditor 增加共享视觉变体，MemoryReceiptCard/来源标签统一状态色。新增 `components/layout/harbour-backdrop.tsx` 仅承担静态装饰，pointer-events:none、aria-hidden；业务状态由现有 hooks/gateway 管理。

连接动画组件 `components/knowledge/connection-preview.tsx` 接收端点和真实状态，只渲染，不请求接口、不改审批。不得新增与原有弹窗同职责的模态组件。所有列表、详情、编辑、服务配置和临时聊天都应经过主题一致性检查，不能只美化首页。

实施次序：先补第4节接口 → 接通完整卡片链路 → 更新主题与共享组件 → 调整所有页面 → 加入状态动效 → 响应式及无障碍验证。动效不会要求新增后端接口；“连接数量”“AI推荐”等无合同字段仍不展示。
