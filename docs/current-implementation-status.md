# 当前实现与联调状态

> 更新：聊天、技能、状态流、取消、重试、历史与引用的最小链路已打通，详见 [最小框架说明](minimal-chat-framework.md)。以下为接入之前的检查快照，配置与测试情况以最小框架说明为准。

本次检查基于当前工作区代码与实际测试；不以历史验收文档替代当前运行结果。未提交 Git。

## 前端基础效果

办公室场景、人物与任务状态、知识书墙双模式、详情编辑、分区、示例知识、技能工具栏、三点菜单与概览收起已具备。主界面采用白色表面和蓝色重点色（#2563eb），按钮、选中态、悬停、焦点与搜索统一处理。分类和角色仍保留各自的辅助识别色。

基础展示可以收尾，后续应优先联调真实业务，而不是继续增加装饰。

## 后端具体程度

- FastAPI 接口、后端令牌认证与 owner 数据隔离、SQLAlchemy / PostgreSQL + pgvector 配置。
- 百炼模型适配、工具调用循环、文件 / 网页 / 记忆工具、来源引用、上下文预算、流式事件、取消和运行追踪。
- 记忆提取、异步任务、候选审核、版本修订、删除、画像与隐私处理。
- 记忆检索有关键词、向量召回和重排实现；知识集合的搜索目前主要是关键词，不能将其当作整个知识墙已完成向量 RAG。
- 知识集合、条目、关联、文件资产、导入导出等有实现。部分 V2 能力默认关闭（memory_v2_enabled=false、intent_planner_enabled=false、检索策略 legacy），需要单独启用和验收。

## 本机运行与测试

- apps/api/.env 不存在；数据库地址、模型密钥、API_TOKEN 未配置。
- 本机 127.0.0.1:8000 和 :5432 检查均为连接拒绝；后端与数据库当前未监听这些端口。
- 前端语法 / 导入检查、测试、生产构建通过。构建保留主资源超过 500KB 的提示。
- 后端本轮全量 pytest：116 通过、1 跳过、3 失败。3 个失败均来自缺失 docs/memory-retrieval-observability-prd.md 的文档检查。
- 通过的后端测试大量使用 SQLite、模型替身和协议替身，不代表当前机器上真实百炼与 PostgreSQL 的联调通过。

## 建议对接顺序

1. 配置并启动数据库、后端、模型；完成健康检查与最小真实调用。
2. 先接通一个聊天闭环：会话创建 → 发起运行 → 流式回答 → 来源 → 失败 / 取消。
3. 映射本地知识分区 / 笔记到后端集合 / 条目，补齐所缺接口与迁移方案。
4. 技能表单接真实运行状态，再接概览真实用量；定时任务单独设计后台调度。
